## 第一阶段：存储基础

应用组件和业务 Hooks 已统一通过 `src/storage/libraryStorage.ts` 读写数据。`src/storage/contract.ts` 中的 `LibraryStorage` 接口覆盖笔记、文件夹、设置、附件、历史、模板、AI 会话、缓存及整库替换。

默认实现仍是 IndexedDB 适配器。统一入口暂时保留原有 `idb*` 导出名作为兼容别名，未来文件后端不需要沿用这些名称。

存储后端应在应用启动时、Hooks 加载数据之前选择。当前不支持在读写任务尚未结束时直接切换活动笔记库。

IndexedDB 适配器负责数据库升级和事务，浏览器启动流程继续负责旧 localStorage 数据迁移。本阶段不会删除或移动现有浏览器数据。

## 备份导入校验

普通备份和加密备份在替换数据前使用同一套校验，支持 v1、v2 备份。

校验涵盖记录结构、必要字段、时间戳、重复 ID、文件夹父级与循环引用、笔记与文件夹关系、正文和历史中的附件引用、头像引用及设置结构。未被引用的文件记录仍允许导入，避免已有孤立附件导致整个备份无法读取。

| 项目             | 限制               |
| ---------------- | ------------------ |
| 备份文件大小     | 256 MB，读取前检查 |
| 解码后附件总大小 | 128 MB，解码前检查 |
| 顶层记录总数     | 100,000 条         |
| AI 聊天消息总数  | 100,000 条         |
| 单个正文字符串   | 1600 万字符        |
| ID 长度          | 256 字符           |
| 标题、文件名长度 | 4096 字符          |

正文或历史引用了不存在的附件时，会拒绝导入。校验不会修改源文件；v1 缺少历史时，返回补充空历史列表的新数据对象。

## 第二阶段：Windows 桌面壳

仓库已添加 Tauri 2 Rust 入口、主窗口权限、Windows NSIS 打包配置、应用图标、固定端口的 Vite 配置和关闭前保存保护。

数据暂时保存在桌面 WebView 自己的 IndexedDB 中。**浏览器与桌面版的数据环境独立，浏览器笔记不会自动出现在桌面版。** 本地文件笔记库完成前，可通过备份导出、导入迁移。

### 关闭窗口前保存

开启自动保存时，关闭操作会等待当前草稿、设置与文件夹保存完成。存在冲突或保存失败时，提示用户并保持窗口打开。

关闭自动保存时，若仍有未保存修改，会提示先按 `Ctrl+S` 保存再关闭。

当前权限未授予文件系统访问或 shell 执行能力。本地笔记库、系统凭据存储、文件对话框、原生导出与打印适配、签名更新属于后续工作。

## 后续文件存储后端的要求

替换 IndexedDB 前，Tauri 文件后端必须提供以下保证：

1. 在同一个受保护的操作内比较基线并写入，包括文件夹、排序、附件元数据。
2. 整库替换具备原子性，或使用可恢复的操作日志。
3. 永久删除笔记时同时处理关联附件与历史，避免部分删除。
4. 数据变化后及时更新或失效索引；笔记 ID 不随路径变化。
5. 先写临时文件再替换原文件，并检测外部编辑和冲突。
6. API Key 存入系统凭据存储，不放进 Markdown 笔记库。

目标是：Markdown 文件作为主数据，SQLite 作为可重建索引；迁移核验完成前保留原有浏览器数据。
